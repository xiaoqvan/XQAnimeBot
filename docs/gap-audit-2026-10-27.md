## 2. 仍然存在的差异（已逐条在代码里确认）

### 2.1 P1：影响功能完整性

| # | 差异 | 现状 | 影响 |
| --- | --- | --- | --- |
| 1 | **`ai_calls` 不写库** | `grep ai_calls crates/` 只有 mongo 插件示例；Agent 调用不落记录 | TS 用它做「同一集别重复问 AI」与费用统计；现在每次新番都真调一次 |
| 2 | **一个索引都没建** | [mongo 插件](../crates/fuyubot-plugin-mongo/src/lib.rs) 有 `ensure_index`，业务侧没调用 | TS `initDb.ts` 建了 6 组（含 `resources {anime_id, episodeId}`、`{anime_id, groups, episode}`、`cache_resources` 唯一索引）；库大了导航与内联查询会全表扫 |

## 3. 刻意偏离（不是缺口，别「修」回去）

| 偏离 | 理由 |
| --- | --- |
| 出图走 Ultralight 子进程，不是 satori/resvg | 宿主主线程归 tokio，cdylib 抢不到 Ultralight 的渲染线程；见 [image-render.md](image-render.md) |
| 老番路径「规则优先、AI 补集数」 | TS 是 AI 优先。规则命中本来就更稳，还省一次请求；**新番路径仍是 Agent 优先**（[newanime.rs](../crates/fuyubot-plugin-anime/src/newanime.rs)） |
| `/jz` 改为两个章节 id 的单集纠正 | TS 的 `ConAnimeInfo` 是「缓存条目接番剧」，现在投放前就定了番剧，要纠正的是已发进正片的那一集；见 [correct.rs](../crates/fuyubot-plugin-anime/src/correct.rs) |
| inline 结果只能是 article 卡 | `inputInlineQueryResultVideo` 的 `video_url` 必须是 HTTP URL，填不了 Telegram 文件 id；选中后发的是原视频，不重传 |
| 数据层在 `anime-core`，插件壳只做翻译 | 可以纯 `cargo test`，不需要 Telegram/Mongo |
| 服务方法同步、调用方自己开线程 | 宿主 `ServiceMethodFn` 只有同步签名（ABI 定死） |
